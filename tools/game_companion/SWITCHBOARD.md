   in a full-log sheet, and is saved in `~/Library/Application Support/Switchboard-<app id>/`.
6. **Mirror.** Start (comment id, thread, first line of the comment) is posted to issue 15 BEFORE the job runs; if that post fails the job

The Switchboard holds no GitHub key and stores none (LC-Manager's fix 1). If `gh` is missing or logged out it reads nothing and starts nothing.
7. **Hard block** (`SwitchboardRules.hardBlock`, before anything starts; rewritten in the Phase 1 polish round). **The rule:** a line is refused only when it ASKS Local Claude to do something AND that same sentence is about money/payments, logins/passwords/secrets, contacting a person, or Moomoo. "Asks" = it reads like an instruction: it starts with an action verb from a list (`requestVerbs`: pay, email, log, check, set, …) or contains "please", "can you", "you should"… Reports, status notes and discussion are never refused ("Amazon refund ~Nov 16 is Matthew's to check", "CBDC hold: no sending until GO", "no secrets in the diff"). Messages to our own crew (Hotline, room, board, an LC chat) aren't "sending to a person". A call/text/phone/contact/nudge/pitch/DM/email verb leading a request is a contact request whoever the person is. The old version refused any comment that merely mentioned "password", "key" or "secret" and blocked 6 ordinary Co-CEO notes on Nov 6 morning. **Refusals now say why** ("hard block: a line asks Local Claude to act on <topic>: "<the line>". Those stay Matthew's. ## Turning ON needs the person at the Mac (Co-CEO blocker, ~5 AM)
- **Why:** in a test an automated (accessibility) click flipped the switch ON past the old click-through alert. Anything that can click, including Friday's own hands, could do the same.
- **Now:** turning ON asks macOS (`LAContext.evaluatePolicy(.deviceOwnerAuthentication, localizedReason: "Turn on Friday's Switchboard")`) for Touch ID or the Mac password. ON happens only in that call's success branch. Cancel, failure, or a Mac that can't ask = it stays OFF and the log says why ("Switchboard stays OFF: Touch ID or Mac password …"). Turning OFF stays one click with no password (safe direction). The old alert is gone.
- **One place:** the switch is changed only by the private function `apply`. `apply(true…)` is called from exactly two marked places: the LocalAuthentication success branch (`ON-PATH: auth`) and `testTurnOn()` (`ON-PATH: test`, guarded by the test-bundle check, dead in the real Helm). `checks/SwitchboardChecks.swift` scans the source for this (13 checks, mutation-tested: adding a third `apply(true` makes it FAIL). Every ON/OFF log line names its source: "Touch ID or Mac password", "the toggle (off)", "the test hook … (test copy only)".
- **Proof:** the system sheet really appears when the toggle is clicked (a `coreautha` window, layer 1000, shows up in the window list; the background screenshot tool can't capture system windows, so there is no picture of the sheet itself). With the test-only `switchboard.testAuthCancel` hook (test bundle only, cancels the sheet after 1 s) the log reads "Switchboard stays OFF: Touch ID or Mac password cancelled by the app (test hook)" and the switch stays OFF (`switchboard-proof/6-auth-cancelled-stays-off.jpg`). Twice earlier, before the hook was shortened to 1 s, someone approved the sheet within about 5 s and the log read "turned on by Touch ID or Mac password": that was most likely Matthew at the Mac; I could not tell who touched the sensor.
- **What this STOPS:** software clicking or typing (accessibility clicks, scripts, Friday's own hands). It can't answer the system sheet.
- **What it does NOT stop:** anyone at the Mac who has Touch ID or knows the Mac password, and anyone who can edit the saved setting directly (`defaults write … switchboard.on`) or run the app's code. A restart while ON resumes watching by design (the saved state is the person's earlier approved choice).
- **Not tested:** the real Helm; the Touch ID path on a Mac without a fingerprint reader (the system falls back to the password); behaviour if the Mac is locked mid-prompt.

## Forgiving names + closed chats (Phase 2 bug fix; Co-CEO, Matthew: "i dont want them getting stuck")
- **Name matching** (`SwitchboardRules.NameMatch`, used by room pings, Hotline relays, hand-offs and the relay proof): ignores case, spaces, `-`, `_`, `:` and punctuation (letters and digits only) and one trailing "s" ("LC-Pixels" = "LC-Pixel", "LC_Manager" = "LC-Manager"). A short name that is a unique prefix of at least 4 letters also matches ("LC-Helm build" = "LC-Helm: build revamp (B v2)"). Exactly one match = deliver. None or two or more = never guess: "not open (closest: <name>)" / "more than one chat matches …". The relay job is taught the same rules in its prompt, and the app re-checks every delivery afterwards from the recorded ListAgents list: a message that went to a different chat than the single match is "not confirmed" (UNPROVEN), never "delivered". Cooldown keys use the same loose name (LC-Pixels and LC-Pixel share one).
- **Closed chat = hand-off at once, no retry loop:** when a room ping or a Hotline relay finds the chat not open, the message goes IMMEDIATELY to the backup manager, Friday (LC-Manager if Friday is the closed one, and as the second choice), labelled `for <name>, whose chat is closed; handle it or reassign: <the original text>` (a room ping's original text is just its link). One line goes to the Hotline per hand-off (`**[Friday (LC-Switchboard) → Claude]** <name> is closed; Friday has it (room message 123).`, names and a reference only, it can't trigger a job, relay or ping). If nobody could take it, the line says so.
- **One held copy:** the original chat still gets the message ONCE when it reopens: a copy is kept (`held.json`, public text only) and probed every 15 minutes (one small relay run per probe, only while something is held), delivered once, then removed; dropped after 12 hours. The delivered copy says "held for you since <time>, when your chat was closed: …".
- **Crew chat text** (`PingResult.badge`): "LC-Pixel closed → Friday has it" while handed off, "LC-Pixel closed, and nobody could take it", "pinged ✓ LC-Pixel (when it reopened)" after the held copy lands. State strings: `handed to <name>`, `closed`, `delivered later`.
- **DMs** are not handed off or held: a closed Friday chat just shows "Friday's chat is closed — open it to talk".
- **Not tested live:** a real hand-off to Friday, the held-copy probe delivering after a reopen, and the Hotline line (checks cover the rules, labels, timings and the delivery proof with synthetic ListAgents output). The probe costs one small run per 15 minutes per held message; lots of messages to a long-closed chat would add up (12-hour cap, hourly wake cap applies).
